# n8n RAG + Airtable AI Agent

An n8n workflow that combines two AI capabilities in one chat assistant:

1. **Structured data agent** – answers questions about bank transactions stored in Airtable (filtering, listing, calculating averages).
2. **RAG (Retrieval-Augmented Generation)** – answers questions about a company policy PDF using a vector store and semantic search.

Ask in plain language, get answers from either source. No SQL, no manual searching through documents.

![Workflow overview](images/workflow.png)

## What it does

| Question | What happens |
|---|---|
| "Show me the last 5 transactions" | The agent queries Airtable and returns only the requested number of records |
| "What is the average transaction amount in category utilities?" | The agent filters records, then uses a code tool to calculate the average |
| "What is the company policy on remote work?" | The agent calls the RAG sub-workflow, which searches the PDF and answers from it |

The agent keeps short conversation memory, so follow-up questions work ("and only the ones above 500?").

## How it works

The workflow has three parts:

### 1. AI Agent (chat)
- **Trigger:** n8n chat message
- **Model:** OpenAI (`gpt-5-mini`)
- **Memory:** Simple Memory (window buffer)
- **Tools:**
  - *Search records in Airtable* – fetches transactions, with the filter formula generated by the AI from the user's question
  - *Get base schema in Airtable* – lets the agent read the table structure before building a filter
  - *Code Tool* – calculates the average transaction amount
  - *Call RAG Workflow* – sends policy questions to the RAG part

### 2. RAG question answering
- **Trigger:** `When Executed by Another Workflow`
- A retrieval QA chain pulls the top 20 most relevant chunks from the vector store and generates the answer with OpenAI.

### 3. Document ingestion
- **Trigger:** manual (`Execute workflow`)
- Downloads the PDF from Google Drive → splits it by pages → creates OpenAI embeddings → stores them in an in-memory vector store.

```
Chat message ─► AI Agent ─┬─► Airtable (search / schema)
                          ├─► Code Tool (average)
                          └─► RAG Workflow ─► Vector Store Retriever ─► Answer

Manual run ─► Google Drive (PDF) ─► Data Loader ─► Embeddings ─► Vector Store
```

## Tech stack

- [n8n](https://n8n.io) (AI Agent, Retrieval QA Chain, Vector Store nodes)
- OpenAI (chat model + embeddings)
- Airtable
- Google Drive

## Setup

### Requirements
- An n8n instance (cloud or self-hosted)
- OpenAI API key
- Airtable account with a table of transactions
- Google account with the PDF you want to query

### Steps

1. **Import** `n8n-rag-airtable-agent.json` into n8n (Workflows → Import from file).
2. **Create credentials** for OpenAI, Airtable (OAuth2) and Google Drive, and select them in the corresponding nodes.
3. **Replace the placeholders:**
   - `YOUR_AIRTABLE_BASE_ID` and `YOUR_AIRTABLE_TABLE_ID` in both Airtable nodes
   - `YOUR_GOOGLE_DRIVE_FILE_ID` in the `Download file` node
   - `YOUR_WORKFLOW_ID` in the `Call RAG Workflow` node: select **this same workflow** (the RAG part lives in it)
4. **Load the document:** click `Execute workflow` on the manual trigger once. This fills the vector store.
5. **Chat:** open the chat window and ask a question.

### Airtable table structure

The example transaction table uses these fields:

`id`, `date`, `transaction_amount`, `currency`, `merchant`, `transaction_type`, `transaction_category`, `account_number`, `card_type`, `country_name`, `location`, `description`

## Limitations

- The vector store is **in-memory**: it is cleared when n8n restarts, so the ingestion step has to be run again. For production, replace it with a persistent store (Pinecone, Qdrant, Supabase, etc.).
- Ingestion handles one PDF; multiple files would need a loop.
- The Airtable agent is tuned for a transactions table. Other tables need an updated system prompt and tool descriptions.

## Possible improvements

- Persistent vector database
- Automatic re-ingestion when a file changes in Google Drive
- Telegram or Slack as the chat interface
- Source citations (page numbers) in RAG answers
